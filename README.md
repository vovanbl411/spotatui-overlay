# Spotatui для Gentoo

Оверлей содержит пакет `media-sound/spotatui`. Это терминальный клиент
Spotify с воспроизведением через librespot. Пакет рассчитан на amd64 с glibc.
Профили musl исключены в ebuild. Для них upstream выбирает `rodio`, тогда как
этот оверлей использует ALSA для Spotify. [Файлы пакета](media-sound/spotatui/) · [Upstream](https://github.com/LargeModGames/spotatui)

## Подключение и синхронизация

С правами администратора создайте `/etc/portage/repos.conf/spotatui-overlay.conf`.

```ini
[spotatui-overlay]
location = /var/db/repos/spotatui-overlay
sync-type = git
sync-uri = https://github.com/vovanbl411/spotatui-overlay.git
auto-sync = yes
```

Оставьте основной репозиторий Gentoo подключённым. Оверлей использует его
eclass и профили. Следующую команду выполните от администратора.

```sh
emaint sync -r spotatui-overlay
```

`-r` выбирает только этот репозиторий. При первой синхронизации Portage
клонирует его в `location`, при последующих обновляет локальное дерево.
`auto-sync = yes` включает оверлей в общую синхронизацию Portage.
Синхронизация меняет дерево репозитория и сама по себе пакеты не обновляет.
[Конфигурация оверлея](metadata/layout.conf)

## Установка и KEYWORDS

В ebuild указан `~amd64` (тестовый keyword). Если профиль принимает только
стабильные пакеты, добавьте запись в `/etc/portage/package.accept_keywords`.
Если это каталог, используйте файл `spotatui` внутри него.

```text
media-sound/spotatui::spotatui-overlay ~amd64
```

Разрешение действует для этого пакета из оверлея. На других архитектурах
запись не делает пакет поддерживаемым. Сначала проверьте план, затем
запустите установку от администратора.

```sh
emerge -pv media-sound/spotatui::spotatui-overlay
emerge --ask media-sound/spotatui::spotatui-overlay
```

`-p` выводит план без установки, `-v` показывает подробности, включая USE.
Суффикс `::spotatui-overlay` выбирает источник пакета. Сверьте версию,
репозиторий, USE и зависимости в плане. После подтверждения `--ask`
Portage установит пакет и запланированные зависимости. Обычная явная
установка может добавить выбранный пакет в world.

## USE-флаги и требования

В ebuild у дополнительных флагов нет значения по умолчанию `+`.
Фактические значения зависят от профиля и ваших настроек Portage.

| USE-флаг | Cargo feature | Назначение и требования |
| --- | --- | --- |
| `cover` | `cover-art` | Обложки в терминальном интерфейсе |
| `internet-radio` | `internet-radio` | Интернет-радио, нужен доступ к потоку станции |
| `local-files` | `local-files` | Воспроизведение поддерживаемых локальных аудиофайлов |
| `mpris` | `mpris` | Управление плеером через MPRIS, нужна сеансовая шина D-Bus |
| `qobuz` | `qobuz` | Источник Qobuz, нужны доступ к сервису и учётная запись |
| `subsonic` | `subsonic` | Источник Subsonic, нужны совместимый сервер и учётная запись |
| `visualizer` | `audio-viz` | Аудиовизуализатор, нужен запущенный PipeWire |
| `youtube` | `youtube` | Поиск и воспроизведение YouTube через `yt-dlp` |

Чтобы включить обложки и MPRIS, добавьте в `/etc/portage/package.use` или
в файл `spotatui` внутри этого каталога следующую строку. При следующем
расчёте Portage покажет оба флага в плане.

```text
media-sound/spotatui::spotatui-overlay cover mpris
```

Для воспроизведения Spotify нужна подписка Spotify Premium.
`media-libs/alsa-lib` требуется при сборке и работе пакета на glibc.
ALSA обслуживает воспроизведение Spotify, в том числе при включённом
`visualizer`. USE-флаг `visualizer` добавляет PipeWire для визуализатора,
`mpris` добавляет `sys-apps/dbus`, а `youtube` добавляет `net-misc/yt-dlp`.
`ffmpeg` может пригодиться для обработки аудио и остаётся необязательным.

Вариант сборки в оверлее отключает стандартный набор Cargo features и явно
включает TUI и Spotify streaming. Самообновление, телеметрия, Discord RPC,
скрипты, AI DJ/MCP, GUI и Soloist в ebuild не включены.
[Описание USE в метаданных](media-sound/spotatui/metadata.xml) · [Принятые ebuild](media-sound/spotatui/)

## Обновление и откат

После синхронизации повторите `emerge -pv` для проверки версии и
зависимостей. Следующая команда обновляет пакет с учётом изменений USE.
Выполните её от администратора.

```sh
emerge --ask --update --newuse media-sound/spotatui::spotatui-overlay
```

`--update` выбирает обновление, `--newuse` учитывает изменения USE,
`--ask` оставляет решение за вами. После подтверждения команда может
обновить зависимости и пересобрать пакет.

Оверлей обычно хранит текущий ebuild и один предыдущий. При новом релизе
текущий становится резервным, а более старый убирается. Посмотрите имена
доступных ebuild в [каталоге пакета](media-sound/spotatui/) своей
синхронизированной копии. В примере замените `<версия>` на предыдущую
версию из имени файла. Включите суффикс `-rN`, если он есть.

```sh
emerge -pv '=media-sound/spotatui-<версия>::spotatui-overlay'
emerge --ask --oneshot '=media-sound/spotatui-<версия>::spotatui-overlay'
```

`=` фиксирует версию, включая ревизию ebuild, а `--oneshot` не добавляет
атом отката в world. Проверьте план перед подтверждением. У пакета один
слот, поэтому установка заменит установленную версию. Следующее обычное
обновление может снова выбрать более новую версию.

Откат зависит от наличия ebuild, distfiles и совместимых зависимостей.
Он меняет пакет, а файлы пользователя, включая настройки, кэш и данные
сеанса, остаются на месте. Совместимость этих данных со старой версией
не гарантируется. Если данные важны, сохраните их перед обновлением
или откатом. После установки проверьте выбранные функции в обычном сеансе.

## Проверки и сопровождение

Для исходного минимального пакета пользователь подтвердил сборку и
воспроизведение Spotify на Gentoo. Это исторический результат для сборки
без добавленных USE-флагов. Он не подтверждает текущую версию или
работу дополнительных функций.

Автоматизация проверяет новые стабильные релизы, готовит метаданные
кандидата и при успешных проверках открывает Draft PR. Решение о принятии
остаётся за владельцем. Сборку и работу клиента проверяют отдельно.
[Как устроена автоматизация](docs/AUTOMATION.md) · [CI, приёмка и восстановление](docs/CI_AND_SECURITY.md)
